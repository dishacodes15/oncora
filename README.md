# Oncora

Federated learning system for clinical diagnosis — brain tumor classification and prescription safety analysis across distributed hospital nodes, without sharing raw patient data.

---

## What it does

**MRI Classification** — Upload a brain MRI scan and get a tumor type prediction (glioma, meningioma, pituitary, or no tumor) with confidence scores.

**Prescription Safety** — Input a prescription and check for dangerous drug interactions with risk-level alerts.

**Federated Monitoring** — Live view of hospital training nodes, global model accuracy across rounds, and federation stats.

---

## Stack

| Layer | Tech |
|---|---|
| Frontend | Streamlit |
| Backend | FastAPI |
| ML Model | CNN (brain MRI classification) |

| Federation | Federated learning across simulated hospital nodes |

## Running locally

**One-time setup — prescription NLP pipeline**
```bash
# 1. Get a free OpenFDA key: https://open.fda.gov/apis/authentication/
cp .env.example .env
# ... fill in OPENFDA_API_KEY in .env

# 2. Install NLP deps (scispaCy's model isn't on PyPI under a normal name —
#    install it via its release URL, per scispaCy's own docs)
pip install -r requirements.txt
pip install https://s3-us-west-2.amazonaws.com/ai2-s2-scispacy/releases/v0.5.4/en_core_sci_sm-0.5.4.tar.gz

# 3. Build the drug vocabulary (pages through OpenFDA — takes a while, run
#    once, then re-run monthly via cron. Do NOT run this at request time.)
python -m backend.nlp.vocab_builder

# 4. Seed the local interaction cache
python -m scripts.init_db
```

**Backend**
```bash
cd backend
uvicorn main:app --reload
```

**Frontend**
```bash
cd frontend
pip install streamlit requests plotly pillow
streamlit run app.py
```

The frontend runs with mock data if the backend isn't running — so you can build and test the UI independently.

**Tests**
```bash
pip install pytest
pytest tests/ -v
```

**Accuracy evaluation (fixed hand-labeled sets, run once)**
```bash
python -m scripts.evaluate_parser
python -m scripts.evaluate_severity
```

**Randomized sanity check (repeatable, tracks accuracy over rounds)**
```bash
python -m scripts.sanity_check --samples 15
```
Draws random known drug pairs from `data/seed_interactions.csv`, runs them through the live pipeline, and appends the result to `docs/nlp_eval_history.json` — visualized in the app's **NLP Sanity Check** tab (same round-based accuracy tracking as the Federated Monitor tab, applied to the NLP pipeline).

**Dose safety checking**
Independent of drug-drug interaction checking — flags a single drug's extracted dose against `data/dose_limits.csv`'s typical max single/daily doses (e.g. "Aspirin 100g" triggers a HIGH dose alert even with no other drug present to interact with). Only mass-based units (mg/mcg/g) are compared; ml/IU/units are skipped rather than guessed at. See `backend/nlp/dose_safety.py`.

## Project structure 
```
oncora/
├── backend/
│   ├── main.py            # FastAPI — /predict-mri, /analyze-prescription
│   └── nlp/
│       ├── parser.py           # spaCy PhraseMatcher: drug + dosage extraction
│       ├── vocab_builder.py    # offline job — builds drug_vocab.json from OpenFDA NDC directory
│       ├── openfda_client.py   # OpenFDA HTTP wrapper (auth, retry, backoff)
│       ├── interaction_store.py # SQLite cache (fast path + self-growing write-back)
│       ├── interactions.py     # orchestrates cache -> OpenFDA fallback -> write-back
│       ├── severity.py         # keyword-rule parser: interaction prose -> HIGH/MEDIUM/LOW
│       ├── dose_safety.py      # single-drug dose vs. typical safe range checking
│       └── schemas.py          # pydantic request/response models
├── data/
│   ├── drug_vocab.json         # generated by vocab_builder.py
│   ├── seed_interactions.csv   # curated starting interactions, loaded by scripts/init_db.py
│   ├── dose_limits.csv         # curated max single/daily dose reference table
│   └── interactions.db         # SQLite store (gitignored — grows at runtime)
├── scripts/
│   ├── init_db.py               # one-time/reset DB seeding
│   ├── evaluate_parser.py       # fixed-set drug extraction accuracy (precision/recall/F1)
│   ├── evaluate_severity.py     # fixed-set severity classification accuracy
│   └── sanity_check.py          # randomized repeatable round-based accuracy check
├── tests/                      # pytest suite for the NLP pipeline
├── frontend/       # Streamlit dashboard
├── notebooks/      # Model training and experimentation
└── docs/
```

### Prescription safety pipeline, at a glance
1. `parser.py` extracts drug names (PhraseMatcher over `drug_vocab.json`) and dosages (regex, sentence-scoped to the right drug).
2. `interactions.py` checks every detected drug pair against the local SQLite store first.
3. On a miss, it queries OpenFDA's drug label endpoint and runs the returned prose through `severity.py`'s keyword rules.
4. Every OpenFDA-derived result is written back to the store — coverage grows automatically as new drug pairs are seen.
5. Low-confidence severity calls (ambiguous or unrecognized phrasing) are flagged rather than silently trusted — see `InteractionStore.low_confidence_pairs()` for a manual-review queue.
